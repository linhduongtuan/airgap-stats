I

Giới thiệu & Mô hình bảo mật

AirGap Stats là gì, dành cho ai, và vì sao kiến trúc 5 giai đoạn của nó khiến việc rò rỉ dữ liệu thật gần như không thể xảy ra — kể cả khi bạn dùng AI để viết toàn bộ code phân tích.

AirGap Stats là gì?

AirGap Stats là bộ công cụ giúp bạn dùng AI coding agent (Claude Code, Codex, hoặc OpenCode) để viết code phân tích thống kê cho câu hỏi nghiên cứu của bạn — mà dữ liệu thật không bao giờ rời khỏi máy của bạn, và AI không bao giờ nhìn thấy nó.

Tên gọi lấy từ thuật ngữ bảo mật “air-gapped” — chỉ một hệ thống bị cách ly vật lý khỏi mạng, không thể bị truy cập từ xa dù có cố ý hay không. Ở đây, dữ liệu thật của bạn được “air-gapped” khỏi AI theo đúng nghĩa đen: AI hoạt động bên trong folder pack, dữ liệu thật của bạn nằm ở một nơi hoàn toàn khác trên máy — AI không có đường nào chạm tới, kể cả khi bạn quên không nói cho nó biết dữ liệu ở đâu.

Bạn không cần biết lập trình R hay Python để dùng AirGap Stats. Việc của bạn chỉ là: mở RStudio, dán vài dòng lệnh agent đưa cho, chọn file khi được hỏi, và dán kết quả quay lại cho agent. AI lo phần viết code; bạn lo phần chạy code trên dữ liệu thật.

Dành cho ai? Hai hướng phân tích

AirGap Stats phục vụ hai loại câu hỏi nghiên cứu khác nhau, mỗi loại có một “track” (hướng phân tích) riêng với phương pháp thống kê riêng (Phần VI so sánh chi tiết cả hai):

  • Medical — nghiên cứu có outcome quan sát được (sống/chết, biến chứng có/không...), dùng hồi quy logistic thô + hiệu chỉnh nhiễu (confounding adjustment). Phù hợp cho nghiên cứu lâm sàng, y sinh, dịch tễ.
  • SEM — nghiên cứu dùng thang đo Likert (bảng khảo sát nhiều câu hỏi đo một khái niệm trừu tượng, ví dụ “mức độ hài lòng công việc”), dùng phân tích nhân tố khẳng định (CFA) + mô hình cấu trúc (structural model) bằng gói lavaan. Phù hợp cho y tế công cộng, khoa học xã hội, khảo sát tổ chức.

Agent sẽ hỏi bạn xác nhận track ngay ở bước D1 — bạn không cần tự quyết định trước, chỉ cần biết mình đang nghiên cứu cái gì.

Cách đọc bảng này khi bạn thấy code AI đưa ra

Nếu một script bắt bạn chọn file qua cửa sổ (file.choose()) hoặc không có đường dẫn mặc định — đó là giai đoạn A/B/C/E, nó cần dữ liệu thật và sẽ luôn hỏi bạn chọn file, không bao giờ tự đoán.

Bốn lớp bảo vệ

  1. Dữ liệu thật nằm ngoài folder pack. Đây là lớp quan trọng nhất, áp dụng cho mọi agent (Claude Code, Codex, OpenCode). AI chỉ hoạt động bên trong folder AirGap Stats — dữ liệu nằm ngoài folder đó nghĩa là nằm ngoài tầm với của AI, vô điều kiện.
  2. Lưới an toàn ở tầng công cụ. Nếu bạn lỡ copy dữ liệu vào một folder như data_real/ bên trong pack, cấu hình của Claude Code có deny rule chặn việc đọc folder đó ở tầng công cụ — không phải chỉ là một lời nhắc AI tự giác tuân theo. Mọi skill cũng có lệnh cấm rõ ràng kèm cảnh báo bạn chuyển file ra ngoài nếu phát hiện.
  3. .gitignore chặn commit dữ liệu. Các đuôi file dữ liệu phổ biến (data_real/, .sav, .dta, .xlsx) bị chặn khỏi git ngay từ đầu — phòng trường hợp bạn dùng git để backup/chia sẻ project.
  4. Cổng QA (dr-output-qa-gate) kiểm tra từng giai đoạn. Trước khi cho phép sang giai đoạn tiếp theo, cổng này xác nhận: file pattern không chứa thống kê/đường dẫn thật, bạn đã xác nhận đã duyệt pattern, và không có dữ liệu thật nào lọt vào repo.

Yêu cầu môi trường

Nếu chọn R + RStudio:

  • R + RStudio (bản R 4.x bất kỳ, tải miễn phí tại posit.co/download/rstudio-desktop). Track Medical chạy 100% base R — không cần cài thêm package nào.
  • Track SEM cần đúng 1 package: chạy install.packages("lavaan") một lần trong RStudio. Nếu dự án của bạn dùng phân tích sống còn (survival analysis), cần thêm package survival — cũng chỉ một lệnh install.packages("survival").

Nếu chọn Python:

  • Python 3.9 trở lên (kiểm tra bằng cách gõ python3 --version trong terminal/Command Prompt).
  • uv — công cụ quản lý môi trường Python, cài một lần theo hướng dẫn ở trang uv (một dòng lệnh, cho cả Windows/macOS).
  • Không cần cài package nào bằng tay từng cái — bước cài đặt bên dưới cài trọn gói một lần, bao gồm cả semopy (bản Python tương đương lavaan) cho track SEM.

III

Dữ liệu thật của bạn để ở đâu?

Phần quan trọng nhất của toàn bộ tài liệu này. Đọc kỹ trước khi chạy bất kỳ lệnh nào trên dữ liệu thật.

Quy tắc vàng

KHÔNG BAO GIỜ copy file dữ liệu thật vào folder AirGap Stats này. Cứ để nó ở nơi bạn vẫn lưu — ví dụ Documents\du-lieu-nghien-cuu\ hay USB. AI agent chỉ hoạt động bên trong folder pack, nên dữ liệu nằm ngoài folder = nằm ngoài tầm với của AI.

Vậy khi script cần đọc dữ liệu thật thì sao? Cách nhập đường dẫn khác nhau tuỳ bạn chọn R hay Python ở Phần II — phần này trình bày R trước (dùng lệnh file.choose(), R sẽ mở một cửa sổ chọn file giống hệt khi bạn mở file Word/Excel, không cần gõ đường dẫn, không cần biết lập trình); mục “Nếu bạn dùng Python” ngay sau đó trình bày cách tương đương cho Python.

Nếu bạn dùng R: từng bước cụ thể (làm đúng 5 bước này mỗi lần chạy trên dữ liệu thật)

  1. Mở RStudio

    Không cần mở project AirGap Stats trong RStudio — chỉ cần RStudio đang chạy.

  2. Trỏ working directory vào folder project của bạn

    Vào menu Session → Set Working Directory → Choose Directory... rồi chọn folder project của bạn (ví dụ ...\projects\diabetes). Bước này để R biết “nhà” của project ở đâu — mọi đường dẫn tương đối trong script (như "pattern/dataset_pattern.csv") đều tính từ đây.

  3. Copy nguyên khối lệnh agent đưa, dán vào Console

    Dán vào ô Console (ô có dấu > ở góc dưới bên trái RStudio), nhấn Enter. Không sửa gì trong khối lệnh trừ khi agent nói rõ cần sửa dòng nào.

  4. Chờ cửa sổ chọn file xuất hiện

    Khi thấy R như “đứng im” — đó là lúc cửa sổ chọn file đã mở (đôi khi nó nấp sau cửa sổ RStudio, hãy nhìn thanh taskbar dưới màn hình). Tìm đến file dữ liệu thật của bạn → bấm Open.

  5. Chờ chạy xong, đọc kết quả

    Chờ chữ chạy xong trong Console, rồi quay lại làm theo hướng dẫn tiếp theo của agent — thường là báo lại “đã chạy xong, không có lỗi” hoặc dán phần output nếu agent yêu cầu.

Nếu bạn dùng Python: không có cửa sổ chọn file, nhưng cùng nguyên tắc

Python thuần không có cửa sổ chọn file kiểu RStudio. Thay vào đó, AirGap Stats dùng hai cách nhập đường dẫn khác nhau tuỳ giai đoạn — cả hai đều giữ nguyên tắc như file.choose(): đường dẫn thật chỉ gõ tại chỗ, không bao giờ được lưu vào file nào trong repo.

Vì sao vẫn an toàn

Cả hai cách đều giữ đúng nguyên tắc của Phần I: đường dẫn thật không bao giờ được agent nhìn thấy, không bao giờ được script ghi vào bất kỳ file .py, .csv, hay file cấu hình nào trong repo. Nó chỉ tồn tại trong phiên terminal của bạn — tắt terminal là mất, giống hệt việc đóng RStudio.

Vì sao cách này an toàn tuyệt đối?

An toàn theo thiết kế, không phải theo lời hứa
  • Đường dẫn tới file thật chỉ tồn tại trong phiên RStudio (hoặc phiên terminal, nếu bạn dùng Python) của bạn — không được ghi vào bất kỳ file nào trong folder pack. AI thậm chí không biết dữ liệu thật nằm ở đâu, tên là gì.
  • Nhờ vậy, toàn bộ folder project của bạn an toàn để zip gửi cho người khác (nhờ giảng viên xem giúp, backup, sync cloud) — trong đó không hề có dữ liệu thật.

Một lưu ý khi paste kết quả cho AI (giai đoạn E)

Nếu trong phần kết quả bạn copy từ Console (R) hoặc terminal (Python) có hiện đường dẫn hoặc tên file dữ liệu thật (ví dụ D:\benh-vien\HIV_2024.csv), hãy xoá dòng đó trước khi paste — vì đôi khi chính tên file cũng là thông tin nhạy cảm (ví dụ tên file chứa tên bệnh viện, tên khoa, hoặc năm + mã bệnh). Với Python, dòng Path to real dataset CSV: ... bạn vừa gõ cũng nên xoá khỏi phần copy trước khi dán cho agent, cùng lý do.

Không bao giờ dán hình ảnh từ dữ liệu thật

Một biểu đồ boxplot hay scatter vẽ từ dữ liệu thật là dữ liệu từng dòng được vẽ thành pixel — một điểm ngoại lai (outlier) trên biểu đồ có thể chính là một bệnh nhân/người tham gia cụ thể, nhận diện được. Bảng số liệu tổng hợp (bảng, ước lượng, khoảng tin cậy, chỉ số fit) thì dán được; hình ảnh vẽ từ dữ liệu thật thì không bao giờ. Các script luôn ghi hình từ dữ liệu thật ra một folder ngoài pack — hình trong outputs_synthetic/figures/ là hình từ dữ liệu giả, mở xem thoải mái.

Trả lời câu hỏi gì

Biến liên tục này (ví dụ tuổi, CRP) có phân phối gần với phân phối chuẩn (hình chuông) hay không? Đây là bước quyết định dùng kiểm định nào ở bốn mục tiếp theo.

Cách đọc kết quả

p ≥ 0.05 → xem như “đủ chuẩn”, dùng kiểm định tham số (Welch). p < 0.05 → dùng kiểm định phi tham số (Mann-Whitney/Kruskal-Wallis). Mẫu quá nhỏ (< 3 điểm) hoặc toàn giá trị giống nhau thì xem như “không chuẩn” — lựa chọn an toàn hơn khi không đủ thông tin để kết luận.

Trả lời câu hỏi gì

Trung bình của một biến liên tục (ví dụ tuổi) có khác nhau giữa 2 nhóm (t-test) hay từ 3 nhóm trở lên (ANOVA) hay không, khi biến đó đủ chuẩn ở mọi nhóm.

Vì sao không dùng t-test/ANOVA “cổ điển”

T-test/ANOVA cổ điển giả định phương sai bằng nhau giữa các nhóm — giả định này thường sai trong dữ liệu thật (một nhóm biến thiên nhiều hơn nhóm kia). Bản Welch không cần giả định đó, luôn an toàn hơn để dùng mặc định.

Cách đọc kết quả

Track SEM — giá trị hội tụ & phân biệt (D3)

AVE & Composite Reliability Fornell & Larcker 1981

Trả lời câu hỏi gì

AVE (Average Variance Extracted): trung bình bao nhiêu phần trăm biến thiên của các item thực sự do construct chung giải thích, thay vì do sai số đo lường. CR (Composite Reliability): độ tin cậy tổng thể của construct, tính từ chính các hệ số tải — cùng công thức họ với omega ở trên, báo cáo riêng theo quy ước ngành.

Cách đọc kết quả

AVE ≥ 0.50 → construct “giá trị hội tụ” tốt (item thực sự đo đúng construct nhiều hơn đo nhiễu). CR ≥ 0.70 → độ tin cậy tổng thể tốt. Đây là hai ngưỡng kinh điển nhất trong tài liệu SEM (Fornell & Larcker 1981), gần như luôn được báo cáo cùng nhau.

HTMT Heterotrait-Monotrait ratio; Henseler, Ringle & Sarstedt 2015

Trả lời câu hỏi gì

Hai construct khác nhau (ví dụ “hài lòng công việc” và “kiệt sức”) có thực sự là hai khái niệm tách biệt, hay thực chất đang đo trùng lặp lẫn nhau (“giá trị phân biệt” — discriminant validity)?

Cách đọc kết quả

HTMT < 0.85 (ngưỡng chặt) hoặc < 0.90 (ngưỡng lỏng hơn) → hai construct đủ tách biệt để coi là hai khái niệm khác nhau. HTMT cao → cân nhắc gộp hai construct lại, hoặc xem lại câu hỏi khảo sát có đang hỏi trùng ý không.

Track SEM — mô hình cấu trúc (D4)

Mediation bootstrap hiệu ứng gián tiếp/trực tiếp/tổng

Trả lời câu hỏi gì

Predictor (ví dụ hài lòng công việc) ảnh hưởng tới outcome (ví dụ ý định nghỉ việc) trực tiếp, hay gián tiếp thông qua một biến trung gian (ví dụ kiệt sức), hay cả hai? Đây là câu hỏi “bằng cách nào” (mechanism), không chỉ “có liên quan không”.

Vì sao cần bootstrap thay vì kiểm định thường

Hiệu ứng gián tiếp = tích của hai hệ số hồi quy (a×b) — tích của hai số không có phân phối chuẩn ngay cả khi từng số một có, nên kiểm định thống kê thông thường (dựa trên giả định chuẩn) không chính xác. Bootstrap tạo hàng trăm mẫu lại từ dữ liệu, tính a×b mỗi lần, rồi lấy khoảng phân vị 2.5%–97.5% của toàn bộ phân phối đó làm khoảng tin cậy — không cần giả định phân phối chuẩn.

Cách đọc kết quả

Khoảng tin cậy 95% (bootstrap) của hiệu ứng gián tiếp không chứa 0 → có trung gian hoá có ý nghĩa thống kê. So sánh hiệu ứng trực tiếp (sau khi đã tính trung gian) với hiệu ứng thô: nếu trực tiếp không còn ý nghĩa → trung gian hoá “toàn phần”; nếu vẫn còn ý nghĩa nhưng nhỏ hơn → “một phần”.

Track SEM — đo lường bất biến (nếu dự án so sánh nhóm)

Đo lường bất biến measurement invariance — configural & metric

Trả lời câu hỏi gì

Nếu bạn so sánh điểm construct giữa hai nhóm (ví dụ nam/nữ, remote/văn phòng), câu hỏi ẩn phía sau: thang đo có đo cùng một thứ theo cùng một cách ở cả hai nhóm không? Nếu không, so sánh điểm số giữa hai nhóm không có ý nghĩa — giống so sánh nhiệt độ đo bằng độ C với độ F mà không quy đổi.

Cách hoạt động

Configural: cùng cấu trúc construct → item được ước lượng riêng ở mỗi nhóm, không ràng buộc gì — chỉ kiểm tra mô hình có fit được ở cả hai nhóm hay không. Metric: ràng buộc hệ số tải (factor loading) phải bằng nhau giữa hai nhóm, rồi so sánh độ fit với mô hình configural bằng kiểm định chi-square khác biệt — fit tệ đi đáng kể nghĩa là hệ số tải thực sự khác nhau giữa hai nhóm.

Cách đọc kết quả

p (kiểm định chi-square khác biệt) ≥ 0.05 → không đủ bằng chứng bác bỏ bất biến ở mức metric — an toàn để so sánh điểm construct giữa hai nhóm. p < 0.05 → ít nhất một item có hệ số tải khác nhau giữa hai nhóm, cần thận trọng khi so sánh trực tiếp.
